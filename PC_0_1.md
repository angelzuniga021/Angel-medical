# Ángel Medical PC 0.1

Primera edición Windows x64 de consulta de instantáneas AMX schema 7,
compatible con exportaciones de Android 3.2. Sin modificar la APK existente.

## Incluye

- Lectura PBKDF2-HMAC-SHA256 (150000 iteraciones) y AES-GCM-256 idéntica al contrato del exportador Android. La autenticación sucede antes de interpretar el contenido.
- Validación de identidad, versión, tablas requeridas, identificadores duplicados, relaciones paciente/hospitalización y SHA-256 de todos los adjuntos.
- Búsqueda por nombre, CURP y expediente; consultas, urgencias, hospitalizaciones, evoluciones, órdenes, documentos, escalas, mediciones, agenda, tareas, borradores y revisiones.
- Datos de perfil recibidos y conteo de todas las tablas para revisión del intercambio.
- Guardado explícito de adjuntos completos y extracción de PDF firmado integrado con comprobación de su huella. Nunca se regenera un PDF firmado.
- Descifrado fuera del hilo de interfaz; apertura fallida mantiene el expediente anterior. Cierre explícito del expediente sin persistencia descifrada automática.

## Alcance

Esta entrega NO crea una base de producción Windows, NO permite editar,
NO sincroniza Drive, NO firma documentos en Windows y NO verifica confianza
SAT/revocación/sello de tiempo. El usuario abre una instantánea nueva para ver
los cambios de Android. `.ambak` sigue destinado a recuperación de Android.
El siguiente hito es almacenamiento cifrado Windows e intercambio bidireccional
con identificadores y versiones por registro, resolución explícita de conflictos
y pruebas de preservación antes de habilitar edición.

## Construcción y distribución

GitHub Actions `Angel Medical PC` construye un paquete Windows x64 con EXE,
DLL, runtime C++ y directorio data. Extraer todo el ZIP. El flujo genera el
runner Windows con Flutter 3.47.2 y conserva el código de la aplicación.
Las copias `desktop/lib/clinical_exchange_*.dart` reflejan los archivos compartidos
de `lib/` y se actualizan desde ellos durante la construcción.

Las pruebas utilizan únicamente datos ficticios. Cubren contraseña incorrecta,
cifrado alterado, adjuntos alterados, relaciones rotas, ID duplicado, versión
incompatible, perfil, puntaje cero, bytes binarios e interfaz de apertura.
La validación con la exportación real del usuario sigue siendo una prueba de
aceptación pendiente; no debe publicar datos de pacientes en el repositorio.
